# Persona library

Personas that hold in any product repo. Setup copies one into `docs/panel/<name>.md` and fills its **What I care about here** list for that project; the lens, the skills and the **Seat when** line stay as written unless Matt changes them. A project change to a library persona stays in the project's copy. A change that every project would want comes back here through a `[skill]` lesson on #137.

| Persona | Panel | Asks |
|---|---|---|
| [FT data journalist](ft-data-journalist.md) | strategic | Does each chart prove the observation it claims? |
| [Brand referee](brand-referee.md) | strategic | Is the product drifting from its own look, feel and design language? |
| [Marketer](marketer.md) | strategic | Would the person this is for understand what it promises, and want it? |

The library holds lenses that don't depend on the domain. The seats that do (the people a product serves, the ways it can fail) are drafted per project in setup.

[`ft-data-storytelling.md`](ft-data-storytelling.md) is the cited rule set the FT data journalist applies.
